# 浦东租住地图 · 三林试点

解压后双击 `index.html`。浏览器可离线运行，无依赖、账号或 Key。上方可以临时导入 JSON，刷新即恢复内置数据。长期修改请编辑 `data.json`，运行 `python3 build.py` 重建页面。请将私有观察单独保存在本地 JSON，分享 HTML 前检查内嵌内容。

## 已验证的起点

- 保利林语溪作为康桥镇对照。康桥镇材料给出秀沿西路68弄、2011年建成、约1878户和历史积水整改计划。房天下另列2010建筑年代。当前积水状态待核，保利林语溪是否为此前讨论项目也待确认。
- 金地湾流域（尚博路518弄）与三林世博家园（大道站路94弄）是门牌级候选与基线对照。其年份和户数留空，避免把相邻分期或整个片区合并。
- 初始库有三条小区档案，零条在租、出售、品质打分和通勤记录。坐标尚未核验，内置地图因此显示空态。可从卡片跳转高德地址搜索。补充经实地核验并允许保存的入口坐标后，地图会画小区分布。页面内部是北向坐标散点图，在线道路底图与自动路线规划属于后续接入。

## 最小格式

根对象含 `version: 1` 和下列六个数组。未知数值用 JSON 的 `null`，可选字段也可省略。日期统一上海本地 YYYY-MM-DD。动态表每行须有 `checkedAt` 与 `source`，后者可为可核查 URL 或本地调查记录索引。

| 表 | 字段 |
| --- | --- |
| communities | id, name, district, area, address, year, households, location, tags, source, note |
| listings | id, communityId, unitKey, status, tenure, monthlyRent, areaM2, areaBasis, bedrooms, checkedAt, source |
| saleSamples | id, communityId, unitKey, kind, totalPrice, areaM2, areaBasis, bedrooms, checkedAt, source |
| quality | communityId, axis, rating, checkedAt, source |
| destinations | id, name, location |
| routes | communityId, destinationId, mode, scenario, km, minutes, checkedAt, source |

- location 为 null 或对象，含 lon、lat、crs（WGS84/GCJ02）、source。建议小区点和路线起点都用常走的入口，目的地用实际公司入口。坐标系不同时不出直线距离。路线场景字符串写明统一出发条件，如工作日早高峰及取样规则。公交、驾车、步行、骑行分别比较，路线记录保留 30 天。当前版本仅导入有权保存的路线记录。
- status 为 active / inactive / unknown。整租 tenure 写 whole。最近 7 天人工确认 active 的整租进入筛选。每个来源记录 ID 唯一。已确认同一套的跨来源记录填同一个匿名 unitKey，并由最新核验决定状态。无法确认的记录可作为观察显示，排除在租售比之外。不要把不同套的同户型误合并。当天冲突需先人工消解，程序同日按文件后出现的记录取值。
- areaBasis 为 gross 表示建筑面积。租金是人民币元/月，售价为人民币元/套，租售比的出售样本 kind 写 asking。只比较同小区、同卧室数及同建筑面积带，两侧各至少 3 个匿名单位，出售挂牌 30 天内。计算 12 × 月租每平方米中位数 ÷ 售价每平方米中位数。样本少时显示计数与待核验。该值用于比较租住相对价格，口径是毛挂牌收益率，未计税费、物业、空置、装修及议价。历史成交应单开指标。
- 房源租金、面积、卧室条件须同时命中同一条房源。初始不设次新硬阈值，用户可改建成年份起点。未知年份在启用阈值时不通过。
- 生产版建议将小区 ID 与别名、门牌、分期和逐字段证据拆表，将源记录及撤牌历史追加写入。先用门牌和分期匹配，再人工复核同名、跨期或疑似重复项。数据流为本地观察或授权导出 → 映射与人工复核 → JSON 校验 → 浏览器聚合。上游授权渠道尚未接入。

## 品质规则

品质是小区层；采光、楼层、户内噪声和装修属于具体房源，应另记。每维 0–4 分，建议 0 为严重影响日常、1 为明显短板、2 为可接受、3 为良好、4 为两次观察均稳定良好。先保存观察证据再填分。同一维采用最近 180 天内的最新已审核记录。覆盖率按权重计，五项齐全才计算总分。权重是试点假设，实际看房后调整。

| axis | 权重 | 现场记录 |
| --- | ---: | --- |
| noise | 30 | 工作日晚间和周末对比，注明沿街与内排、窗内外 |
| property | 25 | 门禁、保洁、报修响应，注明观察时间 |
| space | 20 | 公区步行体验、机动车干扰、绿地实际可达性 |
| access | 15 | 常用出入口、雨天绕行、进出人车冲突；通勤单列 |
| upkeep | 10 | 电梯、楼道、地下室维护及可见渗漏迹象 |

历史积水、轨交或主干道暴露等事实保留标签与来源，单独核验现状。品牌、挂牌价格、年代与户数不直接计分。对雨天积水、噪声这类可能影响选择的事项，先看事实，再看综合分。

## 数据路径与继续开发门槛

| 路径 | 适合拿到 | 局限与处理 |
| --- | --- | --- |
| 公开材料 | 门牌、分期、年份、项目规模、历史治理记录 | 逐项记录来源、口径与冲突。楼盘页价格均值无法补在租观察。 |
| 人工整理／经纪人授权导出 | 小范围整租报价、上下架、面积与现场品质证据 | 每条复核状态、采集时间与允许用途。仅用匿名单位键，避免留电话、门牌到户和原始聊天记录。 |
| 机构授权接口 | 可持续取得上架、撤牌和价格变动，视协议范围 | 先确认浦东覆盖率、延迟、去重 ID、可保存字段、展示及衍生统计权、缓存期限、配额、撤销与删除流程。尚无可用接口被验证。 |
| 上海住房租赁公共服务平台 | 房源核验、备案等服务 | 有面向相关机构的服务安排。核验入口本身不足以证明存在可自由使用的实时市场行情接口。 |

试点估算按个人使用、12 个候选小区、40 条房源观察计算。小区建档每个 15–25 分钟约 3–5 小时，首批房源每条 4–7 分钟约 3–5 小时。每周核验 20–40 条按每条 3–5 分钟约 1–3.5 小时。现场品质调查另计，授权接口费用和工程量待拿到样本及协议后估。排序与地图功能已经可用于测试，最大的持续投入在核验在租状态和补足品质证据。

建议用两周决策。先补 12 个小区、1 个实际通勤目的地、30–40 条整租观察，再看能否连续两周给至少 6 个候选各找到 2 条有面积和报价的近期记录。对照原先手动翻平台的结果，若原型能多找出 2 个愿意实看的小区，值得维持个人工具。若样本达不到门槛，可缩成低频维护的小区档案和看房候选地图。将租售比留给两侧都达到样本门槛的小区。

## 模块与来源

- `model.js` 是可在 Node 或浏览器复用的校验、时效、聚合、评分和距离模块。
- `app.js` 负责界面与本地文件载入，`template.html` 为页面骨架，`build.py` 打包单文件。
- [shanghai-landing-kit（MIT）](https://github.com/chenmisss/shanghai-landing-kit) 提供了快照到静态地图以及先直线初筛再精算的设计参考。
- [rent-radar（Apache-2.0）](https://github.com/xuanyuanli/rent-radar) 提供了基础数据与价格数据分层更新、输入质量检查的参考。
- 原型独立实现，未复制两仓库代码或导入其房源快照。未接入抓取或高德 API。接入地图服务前核对展示、缓存、导出与 Key 使用范围。公开运营前另核对上海房源核验要求、数据来源权限及个人信息处理义务。
- [浦东保利林语溪整改材料](https://www.pudong.gov.cn/pudong-interaction-front/collect/detail/a54ae3fa3dca4a83bdd00e37ecabb797) · [房天下年代口径](https://m.fang.com/xiaoqu/strategy/sh/1210613306.html) · [上海房源核验业务告知](https://zfzl.fgj.sh.gov.cn/ht_txt_show/showdoc1.html) · [高德开放平台服务协议](https://developer.amap.com/pages/terms/)
